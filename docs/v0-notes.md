# おとは v0 実装メモ

企画書（`_claude_work/hisho-san/docs/おとはピアノ/企画書.md`）の v0 仕様を実装した
プロトタイプの、実装中に決めたこと・残したことの記録。

## 企画書からの差分

| 項目 | 企画書 | 実装 | 理由 |
|---|---|---|---|
| 音源 | Tone.js ＋サウンドフォント | Web Audio の自前合成（4 音色） | サウンドフォントは数 MB の外部ファイル＋ライセンス確認が必要で、「完全静的・権利問題なし」と噛み合わない。手触りの確認が目的なのでまず合成音で通した。`Synth.noteOn/noteOff` の形を保てば差し替えられる |
| 楽器 | ピアノ／エレクトーン等 | ピアノ／エレクトーン／オルゴール／ストリングス | 合成で作り分けられる範囲。減衰する系（ピアノ・オルゴール）と持続する系（エレクトーン・ストリングス）を両方入れて、弾き心地の違いが出るようにした |

それ以外の v0 機能一覧は実装済み。

## 実装で判明したこと・注意点

- **A-B リピートは IFrame API に機能が無い。** 再生位置を 100ms 間隔で監視して、終点を
  越えたら始点へ `seekTo` する。速度 0.5 でも取りこぼさない間隔にしてある。
- **打鍵記録の時刻の基準を動画時刻にすると、追従のコードが要らなくなる。** 記録側は
  `player.currentTime()` を刻むだけ、再生側は毎 tick「今の動画時刻」を渡すだけ。
  シーク・A-B リピート・速度変更のすべてがこれだけで通る。
  シークの判定は「時刻が巻き戻った or 0.5 秒以上飛んだ」で行い、そのとき鳴っている音を
  作り直す（`eventsAt`）。
- **同じ鍵を複数の指で押すケースがある。** 鍵盤は pointerId → 鍵 の対応で持ち、
  離鍵は「他の指がまだ同じ鍵を押していないか」を見てから行う。
- **`lostpointercapture` も離鍵として扱う。** 指が画面外へ出たまま離されると
  `pointerup` が来ず、押しっぱなしで鳴り続ける。
- **録音形式はブラウザで違う。** Safari は `audio/mp4`、Chrome は `audio/webm;codecs=opus`。
  `MediaRecorder.isTypeSupported` で選ぶ。
- **oEmbed が失敗しても登録は通す。** 限定公開・オフラインでタイトルが取れないことがある。
  そのときは動画 ID をタイトルにして、登録そのものは成功させる。

- **鍵盤の文字は長押しで選択・翻訳メニューが出た。** `user-select: none` だけでは足りず、
  iOS Safari 向けの `-webkit-user-select: none` と、長押しメニューを止める
  `-webkit-touch-callout: none` が要る。`<input>` の中の選択はこれらの影響を受けないので、
  URL の貼り付けは通常どおりできる（確認済み）。
- **全画面は iPhone だけ対象外。** WebKit は `<video>` 以外の全画面に対応せずメソッドが
  生えていない（iPad は `webkit` 版を持つ）。呼んでも例外すら出ずに何も起きないため、
  事前に判定してボタンごと隠す。実装はいろは（Iroha Paint）の `fullscreen.ts` をそのまま流用。
  対象は特定要素ではなく `documentElement`（部分木を全画面にすると、その外の鍵盤が描画されない）。

- **明るいテーマにしたら、薄い色が軒並み読めなくなった。** 暗い地では十分だった
  `--fg-dim` などが、明るい地では 3.0〜3.6:1 しかない。ふりがな・鍵盤のドレミ・ボタンの
  副ラベルはどれも小さい字なので、4.5:1 以上に置き直した。とくに「くりかえし」の状態表示は
  塗り用の琥珀をそのまま文字色に使っていて **1.45:1** だった（文字用に濃い琥珀
  `--accent-text` を別に用意した）。塗りに使う色と文字に使う色は分けること。
- **アイコンは角丸ではなく背景透過を選んだ。** 28px では角丸の半径が 2〜3px にしかならず
  「四角い板を貼った」感じは消えない。加えて元の小サイズ素材（`icon_cropped.png` 由来）は
  アルファを持たない RGB で、ほぼ白のラベンダー地がヘッダーの上で明るいブロックになっていた。
  透過版をキャラの外接矩形（`getbbox()` + 6% の余白）で切り直してから縮小することで、
  透過とキャラの大きさを両立させた。`apple-touch-icon` と maskable だけは不透明のまま。
- **縦に積むレイアウトで一覧が画面外へ押し出されていた。** 幅いっぱいの 16:9 は縦を食いすぎる
  （800px 幅なら 450px）。動画の高さを `max-height: 34vh` で頭打ちにし、併せて `.stage` を
  スクロール可にした（鍵盤は下に固定のまま）。

- **学習コンテンツの範囲を「音と音名の対応」だけに絞った。** 最初は入門の練習課題
  （音階・5 指ポジション・3 度…）を 10 種類作ったが、外した（commit d771ec1 に残っている）。
  効果の裏付けが無いまま課題の順序を組むことになる上、弾き方に触れる以上は妙なクセを
  付けかねない。**教わるべきことは人から教わるのがよい。** 一方「この音は ド」「ド はこの鍵」
  という対応は誰から習っても同じ事実で、間違った癖の付きようがない。そこだけを扱う。
- **出題は「曲を収録する」ではなく「規則から作る」で解いた。** パブリック
  ドメインの曲を選んでも、版によっては編曲の権利が乗るし、1 曲ずつ調べる手間が永久に続く。
  音の並びそのものは特定の誰かの作品ではないので、規則から組み立てれば権利の判断が要らなくなる。
  曲を増やすたびに調べるのではなく、**調べる作業が発生しない構造**を選んだ。
- **おだいの出しかたを 4 通りに分けた。** ひかる（位置）→ もじ（音名 → 鍵）→ おと（音 → 鍵）
  → おんぷ（五線 → 鍵）。光を追うだけでは音名は身につかないので、光はいちばん下の段としてだけ
  置いてある。出題そのものは同じで、変わるのは見せかただけ。
- **文言は漢字＋ふりがなに統一した。** ひらがなだけの語とふりがな付きの語が混ざっていて、
  どちらの方針なのか読み手に伝わらない状態だった。企画書の指定どおり、漢字＋ふりがなに寄せた。
  ふりがなは文字の上に積まれるので、**枠の上側の余白を多めに取らないとルビが縁にくっつく**
  （「第 N 問」で実際にくっついた）。ボタンの下段ラベルも `small`（0.62rem）のままだと
  ルビが 5px 程度になって読めないので、専用のクラスで 0.8rem を確保している。
- **選択肢は文字だけにした。** 「3つ」の下に「3つ」と添えるような、同じ文言の二重表示に
  なっていた。絵が無いなら下段のラベルは要らない。
- **五線は難しくなかったが、音部記号は諦めた。** 音の位置は「白鍵の並び」で決まるので
  `whiteIndexOf` がそのまま使え、加線も段の計算だけで出る。記号の方は、ベジエで手合わせ →
  渦の中心がソの線に乗らず失敗 → 中心・半径・巻き数から計算する方式に変えて位置は合ったが、
  それでも「それらしい絵」の域を出なかった。**楽譜の記号は形そのものが決まりごとなので、
  中途半端な絵は載せない方がよい**と判断し、「ト音記号」「ヘ音記号」と文字で書くことにした。
  （Unicode の 𝄞 U+1D11E は端末にフォントが無いと豆腐になるので使えず、記号用フォントの
  読み込みは「完全静的・外部依存なし」に反する。）
- **答えたら ◎／✗ を必ず通す。** 間を空けるだけでは「合っていたのか」が分からないまま次が出る。
  間違えたときは同じおだいに戻す（正解 700ms / 不正解 900ms）。クイズ番組のように
  「第 N 問」を出してから次に入る。
- **音のおだいは、鳴った瞬間にキャラを跳ねさせる。** 音だけだと画面に何も起きず、鳴ったことに
  気付けない。絵はどの音でも同じにする（絵が変わると、それが答えの手がかりになってしまう）。
  同じ音が続いても毎回跳ねるよう、クラスを付け直す前に `offsetWidth` を読んでアニメを区切る。
- **「もういちど」ボタンは外し、キャラを押すと鳴るようにした。** 間違えたときは ✗ が消えた
  タイミングで自動的に鳴り直すので、ボタンとしては要らない。ただし**押して聞き直せる手段は
  残した**（鍵盤で当てずっぽうに押すしか聞き直す手が無いと、まちがえの数え方として不当になる）。
- **◎ も ✗ も赤で、◎ をいちばん大きくした。** 答案に赤で丸を付けるのと同じ。形が違うので
  色で分ける必要がなく、色を変えないぶん大きさに振れる。当たったことが離れて見ても分かる。
- **✗ のときに答えの名前を出すのをやめた。** 名前を教えるとその場は進むが、考える機会が消える。
  「もっと 高い おと ⬆」と向きだけ教えれば、自分で探して当てられる。
  **探す過程がそのまま音と鍵の対応になる**ので、こちらの方が目的に合っている。
  ヒントボタンはこれで役目が無くなったので外した。
- **難しさの軸を「はんい」と「いちどに」に分けた。** 最初は「3つの音／5つの音／和音入り」と
  1 本にまとめていたが、それだと何が難しくなったのかが分からない。
  「ぜんぶ」は画面に出ている鍵盤に従うので、**画面に無い鍵が答えになることはない**
  （鍵盤を狭くすると出題もそれに収まる。テストで固定してある）。
- **走っている間は設定を畳む。** 残したままだと、おだいの入る高さが足りず、五線が成績の行に
  重なった。おだいは縦の空きを全部使う。
- **ドリル中の打鍵は、おだいと同じ長さ（750ms）だけ鳴らす。** 指を離した瞬間に切れると、
  ちょんと触れただけのときに おだいの音と聞き比べられない。離鍵での消音を止め、
  鍵ごとに消音を予約する（押し直しでは前の予約を取り消す）。
- **おとあてのタブでは動画の枠を畳む。** ドリルに動画は関係がないので幅をそちらへ回す。
  畳む前に必ず再生を止める。「映像を隠したまま音だけ流す」は規約で不可なので、
  **隠した状態で再生を続けられる作りにしてはいけない**（そもそも音だけ流す用途は支えない）。
- **`hidden` 属性が効いていなかった。** クラス側で `display` を指定していると
  （`.ctl` の inline-flex、`.rec-row` の flex）、ブラウザ既定の `[hidden] { display: none }` に
  勝ってしまう。「もういちど」ボタンが出たままになって気付いたが、**マイクの無い端末で
  録音ボタンが消えない**という、気付きにくい不具合にも繋がっていた。
  個別に `.ctl[hidden]` を足すと書き漏らすので、`[hidden] { display: none !important }` で
  一括して押さえた（個別に書いていた 12 個のルールは削除）。
- **高さのパーセントを積むと、Safari で五線が丸ごと消える。** 2 段で踏んだ。
  1 段目は `.question-body` が `min-height: 0` のまま flex に高さを任せていたこと。
  実測 390×560 の端末では question-body が 10px 程度まで潰れ、親の高さに合わせている
  五線 SVG が 12×10px になっていた。もじの拡大文字や ◎✗ の印も同じ理由で潰れていた。
  `min-height` を与えて枠は直ったが、**iPhone では五線だけがまだ出なかった。**
  2 段目がこれで、`min-height` で確保した高さは CSS 的には「高さ未確定」なので、
  その下で `.prompt-staff` が `height: 100%`、`.staff-svg` が `height: min(100%, 240px)` と
  二段でパーセント参照していると、**Safari はパーセントを解かずに 0 にする**
  （`width: auto` の SVG は viewBox の比率からも幅を出せず、丸ごと消える）。
  Chromium は独自の推定で解いてしまうので手元では再現せず、実機で初めて分かった。
  パーセントと「viewBox から幅を推測させること」の両方をやめて解決：`.prompt-staff` は
  `align-self: stretch` で確定した高さを受け取り、`.staff-svg` は高さを vh の絶対値
  （`clamp(120px, 20vh, 240px)`）で決め、幅は `aspect-ratio` で明示する。
  SVG 自体にも `width`/`height` 属性を付け、CSS が効かない場合でも 140×120 で出るようにした。
  **手元のブラウザで直ったことは、実機で直ったことの証明にならない。**
- **音部記号は出題の起点（ド）で選ぶ。** 鍵盤の左端はファ始まりだが、おとあての出題は
  常に「鍵盤上でいちばん最初に来るド」を起点にしているので（後述）、しきい値は元の
  中央のド(60)に戻せる。60 以上ならト音・それ未満ならヘ音。左端の表示（ファ）に合わせて
  しきい値を 53 にしていた時期があったが、出題の起点を分けたことで理由が消えたので戻した。
- **鍵盤の左端をファにした。** 子供向けピアノの多くが、鍵盤の左端が
  ドではなくファから始まる。それに合わせるため、出題は「ド起点の長調の音階」ではなく
  「左端から白鍵を実際に数える」方式（`whiteKeyFrom`）に変えた。ファ始まりだと C メジャーの
  半音差の表に黒鍵（シ♭）が混ざってしまい、「左から白い鍵 n つ」という前提が嘘になるため。
  ただしこれをそのまま出題の起点にすると、低いファ（左端）が五線で加線 3 本の下（3 本目の
  加線の上）に来てしまい、ぱっと見で読みにくい。**鍵盤の見た目（ファ始まり）と出題の起点は
  分けた。** 出題は `firstCFrom` で「鍵盤上でいちばん最初に来るド」を求め、そこを起点に
  白鍵を数える（`drillWhiteKeys` で、画面右端までのぶんだけを使う）。左端が F3 ならドは
  C4 になり、五線では加線 1 本の上に来て、いちばん教わりやすい位置になる。
- **正解のあとに間が要った。** 間を空けないと、押した音と次のおだいの音が重なって聞き分け
  られない。目でも正解した実感が持てないまま次が出る。**この間の打鍵は判定しない**
  （まだ出ていないおだいを間違い扱いにしてしまうため）。
- **サバイバルは終わったあとが大事。** 何を押すべきだったかを見せないと次に活きないので、
  正解の鍵を光らせ、「こたえは ソ（おしたのは ラ）」と出す。すぐ「もういちど」も出す
  （一覧まで戻らせるとそこで止まる）。
- **終わりを作らない。** タイピング練習と同じで、やめるまで出題が続く。残りが 4 手を切ったら
  継ぎ足す（押し切ってから足すと、一瞬「終わった」状態を通ってしまう）。
- **最高記録は 20 音以上こなしたときだけ更新する。** 数音でやめた記録が残ると、次に届かない
  目標になってしまう。
- **和音は「同時押し」を求めない。** 初心者は指が 1 本ずつ落ちるので、同時を要求すると
  厳しすぎる。`GuidedPractice` は「全部そろったら進む」にしてあり、押せた音は光を消して
  残りが分かるようにしている。
- **押し間違いは何もしない。** 音や色で咎めると萎縮する。進まないこと自体が「ちがう」の
  合図になる（回数は数えているが、やさしい課題へ戻す判断に使うためで、表示していない）。
- **完了後の打鍵を塞ぐ必要があった。** 塞がないと、押すたびに「できました！」が出る。

- **絵文字をやめて自前の SVG にした。** 端末ごとに絵柄も色も変わるので画面が揃わない。
  規格はいろはと同じ（32×32・線は濃い紫・太さ 2・角丸・面は彩度を落とした色）。
  **面に琥珀は使わない**——選んでいるボタンの地が琥珀なので、同じ色を塗ると絵が消える。
  HTML には `data-icon` の印だけ置いて起動時に差し込む（SVG を直接書くと HTML が読めなくなる）。
  最初に描いた亀・耳・五線・文字は絵として通じなかったので描き直した（亀は足と頭が要る、
  文字は「ド」と書くのがいちばん早い）。
- **スライダーの溝が真っ黒になっていた。** `accent-color` だけに任せると、Chrome が溝の色を
  「つまみと対比する色」として自動で決めるため、端末がダークモードだと溝が黒くなる。
  `color-scheme: light` を宣言しても直らず、溝とつまみを自前で描いて解決した。
  **明るい配色で作った画面は `color-scheme` の宣言も要る**（入力欄・チェックボックス・
  スクロールバーが暗く描かれる）。

- **パソコンのキーボードは `event.code`（キーの物理的な位置）で見る。** `key` で見ると
  刻印が配列ごとに変わって揃わない。ただし **`code` と刻印の対応そのものが JIS と US で
  ずれている**ので、US を前提に割り当てて取り違えた（`]` が鳴らず `[` がソになった）。
  JIS では `]` = `Backslash` / `[` = `BracketRight` / `@` = `BracketLeft` / `:` = `Quote`。
  刻印は JIS に合わせてある。鍵盤の左端をファに変えたので、白鍵の並びは A S D F G H J K L ; : ] =
  ファ ソ ラ シ ド レ ミ ファ ソ ラ シ ド。黒鍵の無いところ（シとドの間・ミとファの間）は
  上の段も空ける（左端がファに変わって、黒鍵の隙間の位置が動いたぶん、飛ばすキーは
  R と I から T と I に入れ替わった）。右端の `@`（`BracketLeft`）は `;`(ラ) と `:`(シ) の間の
  ラ♯で、位置どおり。`[`（`BracketRight`）だけは真上の白鍵との対応を 1 つずらし、`]`(ド) の
  上の黒鍵（ド♯）を割り当てた（`[` の真上の隙間＝シとドの間には黒鍵が無く、厳密に合わせると
  キーが 1 つ死ぬ）。
  画面の鍵盤と同じ道を通すので、打鍵の記録も おとあて の判定も、このために書いたコードは無い。
- **おとあての設定画面から説明文を外した。** 毎回目にする画面に説明が居座ると、
  選択肢が下へ押し出されて選びにくくなる。何のための練習かは README と紹介ページにある。
  残った選択肢は縦の真ん中へ寄せた（`justify-content: safe center`。`safe` を付けないと、
  画面が足りないときに上が切れて選べなくなる）。

## 動作確認済み（Chrome / デスクトップ）

- `youtu.be/<id>?si=...` の登録 → oEmbed タイトル取得 → サムネイル表示 → 再生
- 打鍵記録（動画つき）→ シークで戻ると、その時刻で鍵盤が光りドレミが同期する
- A-B リピート（0:48〜0:51 でループすること、区間が端末に保存されること）
- メトロノーム（4 拍のランプが順に点灯）
- 再読み込み後もライブラリ・記録が残ること
- 縦向き（768×1024）でのレイアウト
- 明るいテーマでの光る鍵盤（淡い琥珀＋金の輪郭で、押下の色と見分けられる）
- おとあて：もじのおだいが並んで今の 1 つが強調される・正しい鍵で進み違う鍵では進まない・
  音のおだいでは鍵が光らず文字も出ない・間違えると鳴らしなおす・ヒントで 1.5 秒だけ光る・
  12 手を超えても出題が続く（継ぎ足し）・やめると成績が出る
- おんぷ：左端が F3 でも出題の起点は最初のド（C4）・ト音記号になり、ド（C4）＝1 本目の
  加線の上、レ（D4）＝加線なし（線の間）、1 オクターブ上のド（C5）＝五線の中に出る
  （記号そのものは描かない）
- 正解で「◎ ド」、不正解で「✗ もっと 高い おと ⬆」が出て、不正解なら同じおだいに戻る
- スタートで設定が畳まれ、おだいが縦いっぱいに出る。「終わる」で設定に戻る
- パソコンのキーボード：A D G の同時押しで ファラド が鳴り、離した鍵だけ止まる。
  JIS の刻印どおり右端が ; : @ ] [ = ラ・シ・ラ♯・ド・ド♯と並ぶ。
  URL 入力中は鳴らない。おとあての判定にも効く
- 音のおだい：鳴るたびにキャラが跳ねる。✗ のあと自動で鳴り直して跳ねる。
  キャラを押しても鳴り直り、まちがえの数は増えない
- おとあてのタブに切り替えると、再生中の動画が止まり枠が畳まれる（0:05 のまま進まないことを確認）
- 正解のあと 550ms 空いてから次が出る。その間の打鍵は数えない
- サバイバル：2 音つづけて間違え、「こたえは ソ（おしたのは ラ）」と正解の光が出て終了。
  最高記録が端末に残る

- **楽器の選択は当面出さない。** 合成音でグランドピアノらしさを出そうと 2 通り試したが
  （倍音ごとの減衰＋弦の硬さ＋打鍵音／弦の振動そのものを計算する撥弦モデル）、
  どちらも元の素直な音に及ばず、8a61e6d の音へ戻した（作った版は c9c75c1 に残っている）。
  **より良い音色の作り方が決まるまで、ピアノ 1 種類で使う。**
  仕組みは残してあるので `#instrument-group` の `hidden` を外せば戻る。

- **使い方ページ（`public/howto.html`）に、実在する動画のサムネイルや題名は載せない。**
  他人の著作物なので、資料に固定で載せると権利の問題になる。画面の見本は
  架空の曲（「（見本）ねこの さんぽ」）で組んだ模型にしてある（写しではない）。
  アイコンもアプリと同じ SVG を写して埋めた。絵文字だと端末ごとに絵柄が変わり、
  **画面と見比べたときに一致しない**（使い方の説明では致命的）。

- **iPhone で ◎✗ が切れた。** 印の大きさを画面の高さ（`vh`）だけで決めていたため、
  画面は高いのにおだいの枠が低い端末ではみ出し、`overflow: hidden` で上下が切れた。
  **入れ物の高さに収まる範囲で決める**（`max-height: 100%` + `flex: 0 1 auto` + `min-height: 0`）
  ように直した。`vh` は「画面の高さ」であって「その要素が使える高さ」ではない。
- **狭い画面（〜520px）で文字が軒並み折り返していた。** ヘッダーが 3 行、タブが 2 行、
  鍵盤の「ファ」が 2 行。縦を大きく食うので、説明の一文を畳み、タブと鍵盤の字を詰めた。
  実機のスクリーンショットで初めて分かった類のもの。
